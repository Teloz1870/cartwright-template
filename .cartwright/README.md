# `.cartwright/` — engine release marker

`release.json` records which Cartwright **engine version** this shop was scaffolded from.
It is **auto-generated by Cartwright's release-sync** ([`.github/workflows/sync-to-mirror.yml`](../.github/workflows/sync-to-mirror.yml))
when the template is published — **do not edit it by hand.**

It exists because a scaffolded shop is a one-shot snapshot with no connection back to the
engine: nothing pulls updates automatically. The marker lets Teloz (and you) tell at a
glance which engine version a deployed shop runs, so a published **security advisory**
(see [`CHANGELOG.md`](../CHANGELOG.md)) can be matched against it and a patch shipped.

## Fields

| Field | Meaning |
|---|---|
| `engine` | Always `cartwright`. |
| `channel` | `stable` (a tagged release — what `npx create-cartwright` ships), `next` (bleeding-edge `next` channel), or `source` (the engine dev repo itself, pre-publish). |
| `ref` | The git ref the snapshot was cut from — e.g. `v0.21.0` for a stable release. |
| `version` | Semver derived from `ref` (e.g. `0.21.0`). The source of truth for "which version am I". |
| `commit` | The engine commit SHA the snapshot was built from. |
| `releasedAt` | UTC date (`YYYY-MM-DD`) the snapshot was published. |

> The `version` field in the project's root `package.json` is **cosmetic** and not
> maintained per release — `release.json.version` is the authoritative engine version.
